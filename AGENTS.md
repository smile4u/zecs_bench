# Правила работы с кодом zecs_bench

Действуют все правила из `zecs/AGENTS.md`: комментарии, стиль английского, имена,
код и порядок работы. Ниже то, что относится только к бенчу.

## Честное сравнение

- В одном сценарии entt и zecs делают одну и ту же работу. Если работа не совпадает,
  описание сценария (`about` в `scenario.h`) говорит, чем она отличается.
- Каждая библиотека использует свой обычный способ, если описание сценария не говорит другого.
- Если в zecs нет нужного API, берётся то, что есть, и рядом пишется `// TODO(zecs): ...`.
  Все такие места находятся поиском `TODO(zecs)`.
- Подробности сценариев описываются в коде и в выводе бенча (легенда и `about`),
  а не в `README.md`.
- Код entt и zecs одного сценария стоит рядом, в одном файле `scenario_*.cpp`.

## Замеры

- Замеры «до» и «после» и разбор цифр делаются только по просьбе.
- Код вне замера (отчёт, проверки, подготовка миров) пишется как можно проще.
  Его скорость не важна.
- Код внутри замера не меняется без причины: правка меняет цифры.

## Сторонний код

- picobench обновляется только скриптом `ext/picobench/update.py`. Свои правки picobench
  делаются только через `ext/picobench/picobench.patch`.
- entt лежит в `ext/entt` одним заголовком. Версия указана в `ext/entt/README`.

## Сборка

```
git clone --recursive https://github.com/smile4u/zecs_bench.git
cmake -S zecs_bench -B build
cmake --build build
./build/zecs_bench
```
